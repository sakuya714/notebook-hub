## 割込み
| | 割込み | タスク切替え |
| 一言で | **緊急事態**。何をしていても**強制的に中断** | 仕事を**順番に入れ替える** |
| 起こすもの | **ハードウェア**（入出力・タイマ・異常）。命令が原因のもの（内部割込み）も | **OS**（スケジューラ） |
| 優先度 | **どのタスクよりも上** | タスクの優先度どおり |
+| 止めるには | **割込み禁止** | タスク切替えの禁止（**割込みは止まらない**） |
> 厨房で：割込み＝**火災報知器**（料理を即中断して対応）／タスク切替え＝店長の「**次はこっちを作って**」。タスクの状態は {{02-3}}
( 外部割込み（CPUの外が原因）
- マシンチェック — ハードウェア異常
- タイマ — 一定時間ごと（ラウンドロビン {{02-3}}）
- 入出力 — 入出力の完了
+ ウォッチドッグタイマ — 一定時間で応答なし→割込みで暴走検知・リセット
)
( 内部割込み（自分の命令が原因）
+* SVC — プログラムが**OSの機能を呼んだ**
+ プログラム — ゼロ除算・オーバフロー・不正命令・記憶保護違反
+ ページフォールト — 主記憶にないページを参照 {{02-3}}
)
( コンテキスト（作業の途中経過）
+* コンテキスト — CPUが今やっている仕事の**状態一式**（**プログラムカウンタ**＋**レジスタ**の中身）
+ 退避と復帰 — 今の状態を**退避**→割込み処理は**別のコンテキスト**で動く→終わったら**復帰**して続きから
+ 割込み処理は短く — 処理中は**他の全部が待たされる**。長いとシステム全体の反応が遅くなる
)
! 「割込み＝外から」とは限らない。自分の命令が原因なら内部割込み

## CPUの性能
(
- CPI — 1命令に何**クロック**かかるか（Cycles Per Instruction）。**小さいほど速い**。部品じゃなく**性能の指標**
)
= #MIPS
= 平均CPI ＝ Σ（命令のクロック数 × 出現率）
= 1命令の時間 ＝ CPI ÷ クロック周波数
= MIPS ＝ 1 ÷ 1命令の時間 ÷ 10⁶
= 例）700MHz、CPI＝4×0.3＋8×0.6＋10×0.1＝7 → 700÷7 ＝ 100MIPS
= 割込みで食われる分は引くだけ（100MIPSで毎秒10⁷命令取られたら残り90MIPS）

## 〇PUの仲間（何の計算が得意か）
| 名前 | 得意なこと |
| CPU | **何でも**。複雑な処理（分岐・判断）を**順番に**。コアは少数＝**少数精鋭** |
| GPU | **単純な計算を大量に同時に**（画像・**行列演算**・AIの学習）。コアは数千＝**人海戦術** |
+| FPU | **浮動小数点**（小数）の計算 |
+| NPU | **AIの推論**を省電力で（スマホの顔認識。Apple の Neural Engine） |
+| TPU | Google が作った**機械学習専用**（Tensor） |
+| DSP | **音声・映像の信号処理**（ノイズ除去）。積和演算が得意 |
( 似た名前
+ MPU — CPUとほぼ同じ意味（Micro Processing Unit）
+ MCU（マイコン） — CPU・メモリ・入出力を**1チップ**にした小型コンピュータ（家電・組込み）
)
> 厨房で：CPU＝**料理長**、GPU＝**大量の見習い**（同じ作業を一斉に）。GPUを画像以外に使う GPGPU は {{02-1#CPUを速くする}}、全部を1チップにする SoC は {{02-4#作り方と電力}}

## CPUを速くする
= #+ パイプラインの実行時間
= (命令数N ＋ 段数D − 1) × ピッチP
=   例）N=5, D=4 → 8ピッチ
@fig pipeline | パイプライン（F取出し D解読 R読出し E実行）| 1つずつずらして同時進行。5命令が8ピッチで終わる
( 並列にする・命令の形
- SIMD — 1命令で複数データ（GPUはこれ）。MIMD＝複数命令×複数データ
+ GPGPU — GPUを画像以外（ディープラーニングの行列計算など）に使う
- RISC — 単純・固定長命令でパイプライン向き。CISC＝複雑で多機能
)
( パイプラインを速く
+* パイプラインハザード — 分岐などで先読みがムダになる
+ 投機実行 — 分岐先を予測して先に実行しておく
+ 遅延分岐 — 分岐に影響しない命令を分岐の後ろに置いて先に実行
+ スーパパイプライン — 段数を増やす
+* スーパスカラ — パイプラインを複数並べる。並べ方は**実行時**にハードが決める
+* VLIW — 同時に動かせる命令を**コンパイル時**に1つの長い命令にまとめる
)
( マルチプロセッサ・マルチコア
+* 密結合 — 主記憶を共有・OS1つ。メモリの取り合い（排他制御）で台数に比例して速くならない
+ 疎結合 — 主記憶もOSも別々。通信でつなぐ
+ ホモジニアスマルチコア — **同じ種類**のコアだけ（homo＝同じ）
+* ヘテロジニアスマルチコア — **特徴の異なる**コアを混ぜる（高性能＋省電力、CPU＋GPU）（hetero＝違う）
)

## メモリ
@fig memtree | 半導体メモリの家系図 | 電源を切ったら消える＝RAM（作業机）、消えない＝ROM（本棚）。オレンジは「消し方」で見分ける3つ
( そのほかのメモリ
+ DDR SDRAM — クロックの立上りと立下りの両方で転送（2倍）。DDR2・3・4と倍々
+ ユニファイドメモリ — CPUとGPUが**主記憶（DRAM）を共有**する（M1 など。データのコピーがいらない）
+ FeRAM・相変化メモリ — 新しい不揮発メモリ
)
| | SRAM | DRAM | フラッシュ |
| 電源OFFで | 消える | 消える | **消えない** |
| 中身 | フリップフロップ | コンデンサ＋トランジスタ | 電荷を閉じ込める |
| リフレッシュ | 不要 | **必要** | 不要 |
| 速さ | **速い** | 普通 | 遅め |
| 値段・容量 | 高い・小容量 | 安い・大容量 | 安い・大容量 |
+| 書換え | 何回でも | 何回でも | **回数に上限**（→ウェアレベリング） |
| 用途 | **キャッシュ** | **主記憶** | **USBメモリ・SSD** |
> **S**RAM＝**S**tatic（そのまま**じっと保持**）＝フリップフロップ＝キャッシュ、**D**RAM＝**D**ynamic（電気が漏れるので**補充**＝リフレッシュ）＝コンデンサ＝主記憶
( フラッシュメモリ（不揮発）
+* 書き方 — **上書きできない**。**ブロック単位で消してから**書く。基板から外さず**電気で**書き換え
+* NAND型 — **ページ単位**で読み書き。安くて大容量→SSD・USBメモリ
+ NOR型 — バイト単位。読出しが速い→ファームウェア
+* ウェアレベリング — 書換え回数を各ブロックで**均等に**して寿命を**延ばす**（Wear＝すり減る）
+ ライトアンプリフィケーション — 頼んだ量より**余計に書き込む**現象（書込み増幅）→ 寿命を**縮める**
+ SLC/MLC/TLC/QLC — 1セルに1/2/3/4ビット
)

## キャッシュ
= #実効アクセス時間
= キャッシュ時間 × ヒット率 ＋ 主記憶時間 × (1 − ヒット率)
= 例）10ns・60ns・ヒット率90% → 10×0.9＋60×0.1 ＝ 15ns
! 容量（Mバイト）は計算に使わない。ひっかけで書いてある
(
+ 局所参照性 — 近いうち・近い場所がまた使われる性質。これがあるからキャッシュが効く
+ ダイレクトマッピング — 置き場所が1か所に決まる（指定席）
+ フルアソシエイティブ — どこでもOK（自由席）
+* セットアソシエイティブ — 決まったセットの中ならどこでも（車両指定の自由席）
-* ライトスルー — キャッシュと主記憶に**同時に**書く。一致してるが遅い
-* ライトバック — キャッシュだけ書いて、**追い出されるとき**に主記憶へ。速い
+ コヒーレンシ — キャッシュと主記憶の内容の一貫性
)

## メモリを速く・入出力
(
+* メモリインタリーブ — 主記憶を複数の**バンク**に分けて並列アクセス
-* DMA — **CPUを介さず**主記憶と入出力装置で直接転送
+ チャネル制御 — 入出力チャネルがCPUの代わりに制御
)
( インタフェース
- USB — シリアル。ホットプラグ・バスパワー。USB PDで大電力給電
+ PCI Express・SATA — PC内部のシリアル規格。高速規格はほぼシリアル（パラレルはスキューでずれる）
- 無線（NFC・Bluetooth・ZigBee…） — 届く距離の順の表は {{03-3#無線}}
)
= #HDDのアクセス時間
= 平均シーク時間 ＋ 平均回転待ち時間 ＋ データ転送時間
= 平均回転待ち ＝ 1回転の時間 ÷ 2
=   例）6,000回転/分 → 1回転10ms → 5ms
( ディスプレイ（キーワード1語で）
- CRT（ブラウン管） — **電子ビーム**を当てて光らせる
+ プラズマ — **放電**で出た**紫外線**で光らせる
+* 有機EL — **電圧で自分が発光**。薄い・曲がる・黒がきれい・速い／高い・寿命が短い・大型化しにくい
- 液晶 — **透過する光の量**を変える。光を通すだけなので**バックライトが必要**
+ MEMSディスプレイ — **微小な鏡**を大量に並べ、**向きを変えて光を反射**（プロジェクターのDLP方式）
+ 電子ペーパー（電気泳動型） — 電気を帯びた**白黒の粒**を**電圧で動かす**。表示中は**電気がいらない**（Kindle）
)

## RAID
@fig raid | RAIDの並べ方
(
+ RAID3 — ビット単位＋パリティ専用ディスク
+ RAID4 — ブロック単位＋パリティ専用ディスク（書込みが集中）
+* RAID5 — パリティを分散（RAID4の集中を解消）
+ RAID6 — パリティ2つ。**2台まで**壊れてもOK
+ RAID01/10 — ストライピングとミラーリングの組合せ
)
= #+ RAIDの稼働率（1台の稼働率 u）
= RAID0（2台）  ＝ u²
=   2台とも動く必要
= RAID1（2台）  ＝ 1 − (1−u)² ＝ 2u − u²
= RAID5（5台）  ＝ u⁵ ＋ ₅C₄u⁴(1−u) ＝ 5u⁴ − 4u⁵
=   4台以上動けばOK
= 容量400GBをRAID5で（1台100GB）→ 400＋パリティ100 ＝ 5台

## 信頼性と稼働率
( RASIS
- R 信頼性 — 壊れにくい → MTBF
- A 可用性 — 使える → 稼働率
- S 保守性 — すぐ直る → MTTR
- I 保全性 — データが矛盾しない
- S 安全性（機密性） — 漏れない
)
= #稼働率
= 稼働率 ＝ MTBF ÷ (MTBF ＋ MTTR)
= 直列 ＝ A₁ × A₂
= 並列 ＝ 1 − (1−A₁)(1−A₂)
= 3台中2台以上 ＝ 3A² − 2A³
= 故障率 ＝ 1 ÷ MTBF
= 直列の故障率 ＝ 各故障率の和
@fig availability | 基本情報まとめの図そのまま
(
+ MTBF＝MTTRのとき — 稼働率0.5
+ MTTRを縮める — エラーログ取得・遠隔保守・保守センタ分散
+ 比べる問題 — 2つの式の**差をとって符号を見る**
)
! 稼働率を上げる対策が **MTBFを延ばす**（予防保守・高信頼部品）か **MTTRを縮める**（遠隔保守・エラーログ）かを区別させる問題が出る

## 性能評価
( 速さを測る
- スループット — 単位時間の処理量
- レスポンスタイム — 入力終わり→**最初の応答が出始める**まで
- ターンアラウンドタイム — 投入→**結果が全部出終わる**まで
+ SPECint／SPECfp — 整数／浮動小数点のベンチマーク
+* TPC-C — OLTP（受発注）のベンチマーク。TPC-E＝証券業務
)
( 計画して増やす
+ モニタリング — 実際の稼働状況を測る
+ キャパシティプランニング — 将来の処理量を予測して必要な資源を計画。必要量の見積り＝**サイジング**
-* スケールアウト — 台数を増やす → 参照中心（Webサーバ）向き
-* スケールアップ — 1台を強くする → 更新が多いDBサーバ向き
)
= #+ アムダールの法則
= 全体の速さ ＝ 1 ÷ { (1 − a) ＋ a ÷ V }
=   a：速くした部分の割合、V：その倍率
= 例）60%の処理だけ6倍 → 1 ÷ (0.4 ＋ 0.1) ＝ 2倍
= CPU数 ＝ 必要なCPU時間 ÷ 使用率の上限（2.4秒分÷60% → 4個）

## 作り方と電力
(
+* FPGA — 現場で回路を**書き換えられる**IC。後から変えられる・**開発が早い**・少量向き、でも**1個は高い**
+ FPGAの作り方 — HDLで書く→論理合成→配置配線→書込み。上に作ったCPU＝**ソフトコアプロセッサ**
+ SystemC — C++ベースでハードとソフトを一緒に設計（コデザイン）
+ ダイナミック電力 — 動くと食う。電圧²×周波数に比例
+* クロックゲーティング — 使わない回路への**クロック**を止める
+* パワーゲーティング — 使わない回路の**電源**を切る（リーク電流対策）
+ DVFS — 負荷に応じて電圧と周波数を変える
)
( チップのまとめ方
+* SoC — CPU・GPU・メモリを**1枚のチップ**に作り込む（**Chip**＝1枚のピザ）。例：iPhone の A シリーズ
+* SiP — **複数のチップ**を1つの**パッケージ**に詰める（**Package**＝お弁当箱）
+* ASIC — 特定用途向けの**専用設計**IC。速い・**大量生産なら安い**、でも**作り直せない**
- LSI — 大規模集積回路＝**チップそのもの**（入れ物）。CPU も GPU も LSI の一種
- ファームウェア — 機器に組み込まれた**ソフトウェア**（SoC はハード）
+ MEMS — 微細な機械部品＋電子回路を1つにしたもの
)
! 「**再プログラム**」「**現場で書き換え**」→ FPGA。「特定用途向けの専用設計」→ ASIC
