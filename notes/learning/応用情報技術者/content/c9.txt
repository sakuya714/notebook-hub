@card クロスコンパイラとエミュレータ | 01-1#コンパイラ
| | クロスコンパイラ | エミュレータ |
| やること | 別の環境用の**実行ファイルを作る**（翻訳する） | 別の環境の**ふりをして実行**する |
| 動かす場所 | **相手の環境**（ここでは動かさない） | **その場**で動く |
| 例 | Mac 上で組込み機器用・iPhone 用のアプリをビルド | Mac 上で Android や昔のゲーム機を動かす |

(
+ クロスコンパイラ — 「〜向けに**実行ファイルを生成**」（**Cross＝またがる**：作る場所と動く場所が違う）
+ エミュレータ — 「挙動を**模倣**」「**疑似的に実行**」（**Emulate＝真似る**）
)

@card フラッシュメモリの寿命（ウェアレベリング） | 02-1#メモリ
フラッシュメモリ（SSD・USBメモリ）は**同じ場所に何回も書くと壊れる** → 書き込む場所を全体に**散らして平均的にすり減らす**のがウェアレベリング。消しゴムの同じ角ばかり使うとすぐダメになる、**全部の角を順番に使えば長持ち**
(
+ ウェアレベリング — 書込みを**均等に分散** → 寿命を**延ばす**
+ ライトアンプリフィケーション — 頼んだ量より**余計に書き込んでしまう**現象（書込み増幅）→ 寿命を**縮める**（悪い方）
- デフラグ — **HDD**でバラバラのデータを**並べ直して**速くする → 寿命とは関係なし（SSDには不要）
+ ジャーナリング — ファイルの変更を**ログに記録**して、障害時に復旧しやすくする → 寿命とは関係なし
)
> **Wear＝すり減る、Leveling＝平らにならす**。「フラッシュメモリ」「書換え回数」「寿命を延ばす」→ ウェアレベリング
@end

## データベース
@card キーの種類 | 03-1#キーの種類
例：社員表（社員番号, 免許証番号, 氏名, 生年月日）
| キー | 意味 | 例 |
| スーパーキー | 1行を特定**できる**組なら何でも（**余計な列が入っててもいい**）（Super Key） | {社員番号, 氏名} |
| 候補キー | スーパーキーから余計な列を**削りきった**もの（**極小**）（Candidate Key） | {社員番号}、{免許証番号} |
| 主キー | 候補キーの中から**1つ選んだ代表**（重複不可・NULL不可）（Primary Key） | 社員番号 |
| 代替キー | 主キーに**選ばれなかった**候補キー（Alternate Key） | 免許証番号 |
| 外部キー | **他の表の**主キー（候補キー）を**参照する**列（Foreign Key） | 販売表の「会員番号」 |
**スーパーキー ⊃ 候補キー ⊃ 主キー**の入れ子（日本 ⊃ 大阪 ⊃ 梅田 と同じ）。候補キーから主キーを選んだ残りが代替キー。**外部キーだけ別枠**：上の4つは「自分の表の行を特定する」キー、外部キーは「**他の表とつなぐ**」キー
(
- 外部キー — 「**参照する**」
- 候補キー — 「**極小**」
+ スーパーキー — 「〜を**含む**集合」（極小じゃない）
+ 代替キー — 「**主キー以外で**一意に識別」
)
! 「代理キー（サロゲートキー）」は別物：意味のない連番などを人工的に付けた主キー
@end

@card スタースキーマ | 03-2#DWHと分析
**真ん中に「売上の記録」、周りに「誰が・何を・どこで」の表**を置いた星形の組み方。分析する数字は**真ん中＝ファクトテーブル**に入る
| 表 | 中身 | 例 |
| ファクト（真ん中） | **起きた出来事と数字**（トランザクションデータ） | 「11/3、顧客001が商品Aを**3個**買った」 |
| ディメンション（周り） | **分析の切り口**になる情報（マスタデータ） | 顧客表（名前・住所）・商品表（商品名・単価）・店舗表 |
ファクト＝**レシートの束**（毎日どんどん増える）、ディメンション＝**名簿・商品カタログ**（あまり変わらない）。「**商品別**の売上」「**店舗別**の売上」のように、ディメンションを切り口にしてファクトの数字を集計する
(
+ ファクト — 「**トランザクションデータ**」「**分析の対象**」「**数値**」（Fact＝事実：実際に起きた売上）
+ ディメンション — 「**分析の切り口**」「**属性**」「**マスタ**」（Dimension＝次元：どの角度から見るか）
+ サマリテーブル — 集計した**結果**をあらかじめ保存しておく表
+ ルックアップテーブル — 決まった**値の一覧**（コード表など）
)
@end

## ネットワーク
@card OSI基本参照モデルとプロトコル | 03-3#OSI基本参照モデル
| 層 | 仕事 | 機器 |
| 7 アプリケーション | アプリの通信ルール | ゲートウェイ |
| 6 プレゼンテーション | 文字コード・圧縮・暗号化など**データの形式** | — |
| 5 セッション | 通信の**開始〜終了**の管理 | — |
| 4 トランスポート | **確実に届けるか、速さを取るか** | L4スイッチ |
| 3 ネットワーク | **IPアドレス**で別ネットワークへ（経路選択） | **ルータ**・L3スイッチ |
| 2 データリンク | **MACアドレス**で隣の機器へ | **L2スイッチ**・ブリッジ |
| 1 物理 | ケーブル・電気信号 | **リピータ**・ハブ |
> 上から「**ア・プ・セ・ト・ネ・デ・ブ**」。試験はほぼ**7・4・3・2層**（5・6層はほぼ出ない）。層の番号より「**そのプロトコルが何をするか**」で点になる
( 7層：「〇〇するための約束」系
- HTTP — Webページの送受信（HyperText Transfer Protocol）
- SMTP — メールの**送信**・転送（Simple Mail Transfer Protocol）
- POP3 — メールの**受信**（端末にダウンロード）（Post Office Protocol version 3）
- IMAP — メールの**受信**（サーバ上で管理）（Internet Message Access Protocol）
- FTP — ファイル転送（File Transfer Protocol）
- DNS — ドメイン名 → IPアドレスに変換（Domain Name System）
- DHCP — IPアドレスを**自動で割り当てる**（Dynamic Host Configuration Protocol）
+ SNMP — ネットワーク機器の**監視・管理**（Simple Network **Management** Protocol）
+ NTP — **時刻合わせ**（Network Time Protocol）
- SSH — 暗号化した**遠隔操作**（Secure Shell）
)
( 4層：2つだけ
- TCP — 確認しながら送る。**確実だけど遅い**（Web・メール向き）（Transmission Control Protocol）
- UDP — 送りっぱなし。**速いけど不確実**（動画・通話・DNS向き）（User Datagram Protocol）
)
( 3層：IP・経路・ルータ系
- IP — IPアドレスで宛先へ届ける（Internet Protocol）
- ICMP — エラー通知・疎通確認（**ping**で使う）（Internet Control Message Protocol）
- ARP — **IP → MAC** を調べる（Address Resolution Protocol）
- RARP — その逆。**MAC → IP** を調べる（Reverse ARP）
+ IPsec — IP通信を暗号化（**VPN**で使う）（IP Security）
+ RIP・OSPF・BGP — ルータ同士で**経路情報を交換**する
+ VRRP — **複数のルータを1台に見せて冗長化**。1台が故障しても予備が引き継ぐ（Virtual Router **Redundancy** Protocol）
)
( 2層：MAC・隣の機器系
- イーサネット — 有線LANの規格（CSMA/CDはここ）（Ethernet）
+ PPP — **2点間**をつなぐ（昔のダイヤルアップ）（Point-to-Point Protocol）
+ VLAN — 1台のスイッチを**論理的に分割**する（Virtual LAN）
+ STP — スイッチ間の**ループを防ぐ**（Spanning Tree Protocol）
)
( 解き方：問題文の単語の意味で選ぶ
+ VRRP — 「**冗長化**」「予備」「切り替え（フェールオーバー）」
+ SNMP — 「**監視**」「管理」
- DHCP — 「**自動で割り当て**」
- ARP ／ RARP — 「**IP↔MAC**」
+ STP — 「**ループ防止**」
)
@end

@card LANの送り方（誰がいつ送るか） | 03-3#LANの送り方
会議で「誰が話すか」に例えると
| 方式 | 例え | キーワード |
| CSMA/CD | 静かなら話す。**かぶったら少し待って言い直す** | 「**衝突**」「**ランダム**」 |
| TDMA | **時間割**で話す順番が決まってる | 「**タイムスロット**」 |
| 優先度制御 | **偉い順**にマイクを渡す | 「**順位付け**」 |
| トークンパッシング | **輪になってマイクを回す** | 「**環状**」「**巡回**」 |
| CSMA/CA | 静かでも**少し待ってから**話す（無線） | 「衝突を**回避**」「ACK」 |
! **「衝突」が出たら CSMA/CD**。TDMA・優先度制御・トークンパッシングは、ぶつからないように**最初からルールで順番を決めている**ので「衝突」という言葉はそもそも出てこない（CSMA/CA は無線で衝突を**避ける**方）
@end

@card IPアドレスの種類 | 03-4#IPv4-アドレスの種類
**プライベートアドレスの範囲3つを覚えておけば**ほぼ解ける
| クラス | プライベートの範囲 | 覚え方 |
| A | 10.0.0.0 〜 10.255.255.255 | 「**10**」で始まる |
| B | 172.16.0.0 〜 172.31.255.255 | 「**172の16〜31**」 |
| C | 192.168.0.0 〜 192.168.255.255 | 家のWi-Fiでよく見る「**192.168**」 |
(
- プライベート — 社内や家の中**だけ**で使う番号。ネット上では使えない
- グローバル — インターネット上で**世界に1つだけ**の番号。**この3つ以外は基本グローバル**
)

| クラス | 最初の数字 | 先頭ビット | 用途 |
| A | 0〜127 | **0** | 大規模 |
| B | 128〜191 | **10** | 中規模 |
| C | 192〜223 | **110** | 小規模 |
| D | 224〜239 | **1110** | **マルチキャスト** |
| E | 240〜255 | **1111** | 実験用 |
> 境目は **128・192・224・240**。先頭に1が1個ずつ増えるだけ：1000 0000＝128、1100 0000＝192、1110 0000＝224、1111 0000＝240
( 特殊なアドレス
+ マルチキャスト — **特定のグループ**に一斉送信。クラスD（224〜239）
- ブロードキャスト — **ネットワーク内の全員**へ。**ホスト部が全部1**（クラスCなら最後が .255）
- ネットワークアドレス — **ホスト部が全部0**。ネットワーク自体を表す番号
- ループバック — **127.0.0.1**。自分自身を指す
)
解き方（消去法なら2進数にしなくても10秒。例：208.77.188.166）
1. プライベートの範囲（10／172.16〜31／192.168）に入ってる？ → 入ってない
2. マルチキャスト（224〜239）？ → 208 なので違う
3. ブロードキャスト（最後が255）？ → 166 なので違う
4. 残りは → **グローバルアドレス**
> 今はクラスを使わず **CIDR**（Classless Inter-Domain Routing：サイダー）で「/24」のように範囲を自由に区切るのが主流。それでも試験ではクラスの知識が出る
@end

## セキュリティ
@card 入口の守り（FW・IDS/IPS・WAF） | 03-5#入口を守る
インターネット → **FW → IDS/IPS → WAF** → Webサーバ の順。内側ほどパケットの**中身を深く見る**けど、守れる範囲は**狭く専門的**になる。3枚重ねで守る考え方＝**多層防御**（Defense in Depth）
( FW（ファイアウォール）＝門番：住所と入口番号だけ確認
- 主な層 — 3・4層
- 何を見る — **IP・ポート番号**（ヘッダだけ）
- 防げる — 許可していない**ポート・IP**からのアクセス
- 防げない — **許可したポート内**の攻撃（例：443番経由のSQLインジェクション）
)
( IDS／IPS（Intrusion Detection／Prevention System：侵入検知／侵入防止システム）＝監視カメラ／警備員
- 主な層 — 3〜7層
- 何を見る — 通信全体の**パターン・異常**
- 防げる — **ポートスキャン**・**DoS攻撃**（サービス妨害）・既知のワームや攻撃パターン
- 防げない — Webアプリ特有の細かい攻撃・**暗号化された通信**の中身
- IDS ／ IPS — 見つけて**通知するだけ** ／ 見つけて**遮断までする**（通信の経路上に置く）
)
( WAF（Web Application Firewall）＝受付：荷物の中身まで開けて確認
+ 主な層 — 7層（**HTTP/HTTPS**）
+ 何を見る — **HTTPの中身**（ペイロード）
+ 防げる — **SQLインジェクション**・**XSS**・**OSコマンドインジェクション**・**ディレクトリトラバーサル**
+ 防げない — **HTTP以外**（DNS・メールなど）
)
| 検知方式 | 仕組み | 強み・弱み |
| シグネチャ型 | 既知の攻撃パターン（シグネチャ）と照合（Signature-based） | 既知に強い。**未知は見逃す** |
| アノマリ型 | 「普段と違う」動きを検知（Anomaly-based） | **未知も見つかる**。ただし**誤検知が多い** |
(
+ フォールスポジティブ — **誤検知**：正常な通信を**攻撃と判定**してしまう（False Positive）
+ フォールスネガティブ — **検知漏れ**：攻撃を**見逃す**（False Negative）
)
( 3枚の壁で守れない攻撃（狙う相手 → 対策）
- DNSキャッシュポイズニング — DNSサーバ → **DNSSEC**（DNS Security Extensions）
- メールボム（大量メール） — メールサーバ → **スパムフィルタ**
- 第三者中継 — メールサーバ（SMTP）→ SMTPサーバの設定で**中継を禁止**
)
( 見分け方
- FW — 「**IPアドレス・ポート番号で制御**」
- IDS ／ IPS — 「不正侵入の**検知・通知**」／「**検知して遮断**」
+ WAF — 「**SQL・XSS・Webアプリ**」
+ どれでもない — 「**DNS・メール**」が対象 → 3枚の壁は関係ない（上の表の別の対策）
)
@end

@card 脆弱性の名札（CVE・CWE・CVSS…） | 03-6#脆弱性の名札
脆弱性情報を**世界共通のルールで管理するための「名札」セット**。頭は全部 **C＝Common（共通）**なので、**2文字目以降の英単語**で区別する
| 略称 | 正式名称・日本語 | 何に名札をつける？ |
| CVE | Common **Vulnerabilities** and Exposures（共通脆弱性識別子） | **個別の脆弱性**1つ1つ |
| CWE | Common **Weakness** Enumeration（共通脆弱性タイプ一覧） | 脆弱性の**種類**（タイプ） |
| CCE | Common **Configuration** Enumeration（共通セキュリティ設定一覧） | セキュリティの**設定項目** |
| CPE | Common **Platform** Enumeration（共通プラットフォーム一覧） | **製品**（OS・アプリ・機器） |
| CVSS | Common Vulnerability **Scoring** System（共通脆弱性評価システム） | 脆弱性の**深刻度を点数化**（0.0〜10.0） |
> 英単語の意味で覚える：**V**ulnerability＝脆弱性 → 個別の脆弱性、**W**eakness＝弱点 → 弱点の種類、**C**onfiguration＝設定、**P**latform＝土台 → 製品、**S**coring＝採点 → 点数
( Log4j の脆弱性で全部つなげると
+ CPE — どの製品？ → Apache Log4j
+ CVE — どの脆弱性？ → CVE-2021-44228（**個別の番号**）
+ CWE — どんな種類の弱点？ → **タイプごとの番号**（SQLインジェクションなら CWE-89）
+ CVSS — どれくらいヤバい？ → 10.0（最高）
)
! **CVE＝事件ごと**の番号（この製品のこのバグ）、**CWE＝手口の種類**の番号（SQLインジェクションなど）。ここが一番のひっかけ
> **SCAP**（セキュリティ設定共通化手順）＝ CVE・CCE・CPE・CVSS と検査用の言語（XCCDF・OVAL）をまとめて点検を自動化する仕組み。たまに選択肢に出る。**CWE は SCAP に入っていない**
@end

@card 似た名前の「コード」 | 03-6#攻撃の手口
家の防犯に例えると
| 名前 | 一言で | 例え |
| エクスプロイトコード | **脆弱性を突く**攻撃用コード | 壊れた鍵を開ける**合鍵** |
| MAC | **改ざんを見つける**ためのコード（Message Authentication Code：メッセージ認証符号） | 封筒の**封印シール** |
| シグネチャコード | マルウェアを**見分ける**ための特徴（定義ファイル） | **指名手配の顔写真** |
| ワンタイムパスワード | **毎回変わる**認証コード | **使い捨ての合言葉** |
> エクスプロイトコードは**攻撃にも、守る側の検証**（脆弱性が本当にあるかの確認）**にも使える**。合鍵と同じで、泥棒が使えば悪用、鍵屋が使えば点検。**Exploit＝悪用する・つけ込む**
( 見分け方
+ エクスプロイトコード — 「脆弱性を**悪用**」「**攻撃コード**」
+ MAC — 「**改ざん検知**」「シークレットデータ＋**ハッシュ**」
+ シグネチャ — 「マルウェアの**特徴**」「**定義ファイル**」
+ ワンタイムパスワード — 「ログインの**たびに変化**」
)
@end

## 開発・マネジメント
@card モジュール結合度と強度 | 04-1#結合度と強度
**結合度**（Coupling）＝モジュール**同士**のつながり → **弱いほど良い**。**強度**（Cohesion・凝集度）＝モジュール**内部**のまとまり → **強いほど良い**。合言葉は「**疎結合・高凝集**」（外とはゆるく、中はしっかり）
| 結合度（良い順） | 何を共有・受け渡しする？ |
| ① データ結合 | 引数で**単一のデータ**（Data Coupling） |
| ② スタンプ結合 | 引数で**構造体**（レコード）（Stamp） |
| ③ 制御結合 | 引数で**動作を指示**（フラグなど）（Control） |
| ④ 外部結合 | **グローバル変数**（単一）（External） |
| ⑤ 共通結合 | **グローバルな構造体**（Common） |
| ⑥ 内容結合 | 相手の**内部を直接**いじる（Content） |
> 語呂「**です、背が今日ない**」＝**デ**ータ→**ス**タンプ→**セ**イギョ→**ガ**イブ→**キョウ**ツウ→**ナイ**ヨウ。3グループで見る：引数で渡す（①〜③）／グローバルで共有（④⑤）／中身を直接いじる（⑥）。「**単一 → 構造体**」の順に悪くなるパターンが2回出てくる
| 強度（良い順） | まとめた理由 |
| ① 機能的強度 | **1つの機能**だけ（Functional） |
| ② 情報的強度 | **同じデータ**を扱う機能を集めた（入口は別々）（Informational） |
| ③ 連絡的強度 | 同じデータを使って**順番に**処理（Communicational） |
| ④ 手順的強度 | 決まった**手順の順**に並べた（Procedural） |
| ⑤ 時間的強度 | **同じタイミング**で動く（例：初期化処理）（Temporal） |
| ⑥ 論理的強度 | **似た処理**をまとめて、フラグで切り替え（Logical） |
| ⑦ 暗合的強度 | **たまたま**寄せ集めただけ（Coincidental） |
> 語呂「**気丈に連れて、持論案**」＝**キ**ノウ→**ジョウ**ホウ→**レン**ラク→**テ**ジュン→**ジ**カン→**ロン**リ→**アン**ゴウ。**まとめた理由がちゃんとしてるほど強い**：1機能 → 同じデータ → 手順 → 時間 → 似てるだけ → 偶然
( 見分け方（問題文の言葉）
- データ・スタンプ・制御 — 「**引数**」→ 中身が単一か、構造体か、指示か
- 外部・共通 — 「**大域・グローバル**」→ 単一なら外部、構造体なら共通
- 内容 — 「**内部を直接参照**」「**JUMP**」
)
! 「引数」だけ見てデータ結合系と決めない。引数で**動作を指示**していたら**制御結合**
@end

## ストラテジ・法務
@card EAの参照モデル | 06-1#EA
4つの体系 → 5つの参照モデル
| 体系 | 参照モデル | キーワード |
| BA | **BRM**（Business Reference Model：政策・業務参照モデル） | **業務**の分類 |
| 〃 | **PRM**（Performance Reference Model：業績測定参照モデル） | **KPI**・投資効果 |
| DA | **DRM**（Data Reference Model：データ参照モデル） | データの**名称・定義・属性** |
| AA | **SRM**（Service Component Reference Model：サービスコンポーネント参照モデル） | 機能の**部品化・再利用** |
| TA | **TRM**（Technical Reference Model：技術参照モデル） | **技術**の標準化（土台） |
体系：BA＝政策・業務体系（Business Architecture）、DA＝データ体系（Data Architecture）、AA＝適用処理体系（Application Architecture）、TA＝技術体系（Technology Architecture）
> 頭文字は英語そのまま：**B**usiness＝業務・**P**erformance＝業績・**D**ata＝データ・**S**ervice Component＝部品・**T**echnical＝技術
! 部品**そのもの**の分類 → **SRM**、部品を**動かす土台**（プラットフォーム・技術） → **TRM**
@end

@card 半導体の分業 | 06-1#分業のかたち
| 名前 | 企画・設計 | 製造 | 販売 |
| 垂直統合型（IDM） | ○ | ○ | ○ |
| ファブレス | ○ | × | ○ |
| ファウンドリ | × | ○ | × |
| デザインハウス | ○ | × | × |
(
- 垂直統合型デバイスメーカー（IDM） — **全部自社**（Integrated Device Manufacturer）。例：Intel・Samsung
+ ファブレス — **工場なし**。設計して売る（Fabless）。例：Apple・NVIDIA
+ ファウンドリ — **製造だけ**請け負う（Foundry）。例：TSMC
+ デザインハウス — **設計だけ**請け負う（Design House）
)
> **Fab＝工場**（fabrication）。ファブ**レス**＝工場**なし** → 設計＋販売。ファウンドリ＝**鋳造所**（工場）→ 製造だけ。**Apple（ファブレス）が設計して TSMC（ファウンドリ）が作る**＝**水平分業**
! 「フランチャイザー」は半導体と無関係（コンビニ本部のように、商標と販売権を貸す側）
@end

@card パーミッションマーケティングと仲間 | 06-1#売り方
| 手法 | 一言で | 例 |
| パーミッション | 客の**同意（許可）をもらってから**売り込む。同意の範囲を**少しずつ広げる** | メルマガ登録・LINE友だち追加・無料サンプル |
| アフィリエイト | **成約したら報酬**を払って、他人のサイトで紹介してもらう | ブログの Amazon リンク |
| バイラル | **口コミで勝手に広まる**仕組みを作る（viral＝ウイルスのように） | SNSでバズる・シェアキャンペーン |
| 差別型 | **客層（セグメント）ごとに**売り方を変える | 若者向けと高齢者向けで別の広告 |
パーミッションの流れ（LINE公式で）：①友だち追加で**クーポン**（きっかけ）→ ②追加した人に**少しずつ**情報を送る → ③「誕生日も教えて」と**同意の範囲を広げる** → ④**常連客**になってもらう
( 見分け方（Permission＝許可。許可をもらってから売る）
+ パーミッション — 「**同意**」「**許可**」
+ アフィリエイト — 「**成功報酬**」
+ バイラル — 「**口コミ**」「**自然に広がる**」
+ 差別型 — 「**セグメントごとに違う**」
)
@end

@card 投資するか決める指標 | 06-2#投資するか決める指標
4つとも**投資するべきか判断する指標**。例：100万円投資して、毎年30万円もうかる
| 指標 | 何を見る？ | 例での答え |
| ROI | 投資に対して**何%**もうかるか（Return On Investment） | 30万 ÷ 100万 ＝ **30%** |
| PBP | **何年で**元が取れるか（Pay Back Period） | 100万 ÷ 30万 ≒ **3.3年** |
| NPV | 将来のもうけを**今の価値**に直して、投資額より大きいか（Net Present Value） | **0より大きければGO** |
| IRR | NPVが**ちょうど0**になる利回り（Internal Rate of Return） | **期待する利回りより大きければGO** |
> **現在価値**とは：来年の100万円は、今の100万円より価値が低い（今もらえば利息がつくから）。だから将来のお金は**割り引いて**比べる。NPV と IRR はこの考え方を使う
( 見分け方（日本語名もセットで）
- PBP（回収期間） — 「**期間**」「**何年で回収**」
- ROI（投資利益率） — 「**利益 ÷ 投資額**」「**割合**」
+ NPV（正味現在価値） — 「**現在価値**」「**0を上回るか**」
+ IRR（内部収益率） — 「**割引率**」「**内部収益率**」
)
@end

@card 知的財産権 | 06-3#知的財産権
**4つだけじゃない**。全体はこう
(
+ 産業財産権（特許庁に登録が必要） — 特許権・実用新案権・意匠権・商標権
- 著作権 — **登録不要**。作った瞬間に発生
- その他 — **営業秘密**（不正競争防止法）・**回路配置利用権**（半導体の回路設計）・**育成者権**（植物の新品種）
)
| 名前 | 守るもの | 期間 |
| 特許権 | **発明**（高度な技術アイデア） | 出願から**20年** |
| 実用新案権 | **ちょっとした工夫**（形・構造） | 出願から**10年** |
| 意匠権 | **デザイン**（見た目） | 出願から**25年** |
| 商標権 | **ロゴ・名前** | 登録から**10年**（**更新すれば永遠**） |
| 著作権 | **表現**（文章・音楽・プログラム） | 作者の**死後70年** |
| 営業秘密 | **社外秘の情報**（顧客名簿・製法など） | 秘密である限り |
( よく出るポイント
- 登録 — **著作権は登録不要**。他は基本的に**登録が必要**
- プログラム — 著作権で**守られる**。でも**アルゴリズム・プログラム言語・規約**は**守られない**（表現じゃなくて考え方だから）
+ 営業秘密の3条件 — **秘密管理性**（ちゃんと秘密として管理）・**有用性**（役に立つ）・**非公知性**（世間に知られてない）
)
( 見分け方（定義文のキーワード）
- 特許 — 「**自然法則**」「**技術的思想**」「**高度**」
- 実用新案 — 「**物品の形状・構造**」（高度じゃない）
- 意匠 — 「**美感**」「**視覚**」
- 商標 — 「**標章**」「**商品や役務**」
- 著作権 — 「**思想・感情の表現**」
)
@end
