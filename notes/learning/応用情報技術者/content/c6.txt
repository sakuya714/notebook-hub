## EA（エンタープライズアーキテクチャ）
@stack EAの4体系 | 上ほど抽象的（仕事）、下ほど具体的（機械）。右は作るときに参照するモデル
ビジネス（BA）政策・業務体系 :: 業務の流れ → DFD・業務流れ図（WFA）｜BRM・PRM
データ（DA）データ体系 :: データの構造 → E-R図｜DRM
アプリケーション（AA）適用処理体系 :: システムの機能構成｜SRM
テクノロジ（TA）技術体系 :: ハード・ネットワーク｜TRM
@end
( 参照モデル（頭文字は英語そのまま）
+ BRM — **業務**の分類（**B**usiness）。政策・業務参照モデル
+ PRM — **KPI**・投資効果の測り方（**P**erformance）。業績測定参照モデル
+ DRM — データの**名称・定義・属性**（**D**ata）
+* SRM — 機能の**部品化・再利用**（**S**ervice Component）
+* TRM — **技術**の標準化＝部品を動かす**土台**（**T**echnical）
)
! 部品**そのもの**の分類 → SRM、部品を**動かす土台**（プラットフォーム・技術） → TRM

## 業務を直す
(
-* BPR — 業務を**抜本的に**作り直す（一回きり）
-* BPM — 業務を**継続的に**回して改善（PDCA）
- BPO — 業務ごと外部に委託（海外ならオフショア）
- RPA — 定型の事務作業をソフトウェアロボットで自動化。業務の手順は**そのまま**
+ ECRS — 改善の順番：排除→結合→交換→簡素化（まず「やめられないか」）
+ BPMN — 業務の流れを統一の記法で描く
)
> 掃除で：BPR＝**大掃除**／BPM＝**毎日の掃除**／BPO＝**業者に丸投げ**／RPA＝**ルンバ**／ECRS＝**片付けの順番**（捨てる→まとめる→並べ替える→楽にする）

## 売り方（マーケティング）
@flow セグメンテーション::市場（客）を分ける > ターゲティング::どこを狙うか決める > ポジショニング::競合と比べた自社の立ち位置 || STP。セグメンテーション＝「区切る」。OSのメモリ管理のセグメンテーション {{02-3#仮想記憶}} とは分けるものが違う
( 市場と客を分析する
+ セグメンテーション変数 — 地理的・人口統計的・心理的（ライフスタイル）・**行動的（使用頻度・ロイヤリティ）**
+ PEST — 政治・経済・社会・技術（マクロ環境）
- 3C — 顧客・競合・自社
)
| 分析 | 何がわかる | 例 |
+| コンジョイント | 客が**どの要素（価格・機能・デザイン）をどれだけ重視**するか。**組合せ**に順位を付けてもらう | 価格とカメラ性能のどっちを優先？ |
+| コレスポンデンス | ブランドとイメージの関係を**散布図（マップ）**にする | 「高級」「若者向け」の軸で各社の位置 |
+| コーホート | **同じ時期・同じ世代のグループ**ごとに行動を追う | 2020年に登録した人が何年使い続けたか |
+| RFM | 最新購買日・頻度・金額で客を分ける（デシル分析＝購買金額で10等分） | 最近よく高額を買う客＝上得意 |
| パレート（ABC） | 売上の**高い順**に並べて、**重要な客・商品**を見つける | 上位2割の客で売上の8割 |
( 狙い方と確かめ方
+ 差別型マーケティング — **セグメントごとに**売り方を変える（無差別型＝全部同じ、集中型＝1つに絞る）
+ マス／ワントゥワン — **全員に同じもの**を売る（テレビCM。分けない＝無差別型の考え）／客**1人ひとり**に合わせる（購買履歴でおすすめ）
+ AIDMA → AISAS — 注意・興味・欲求・記憶・行動 → ネット時代は**検索・共有**が入る
+ A/Bテスト — 2パターンを出し分けてコンバージョン率を比べる
)
| 4P（売り手） | 4C（買い手） |
| Product 製品 | Customer Value 顧客価値 |
| Price 価格 | Cost 顧客の負担 |
| Place 流通 | Convenience 利便性 |
| Promotion 販売促進 | Communication コミュニケーション |
( 売り込み方（ネット時代）
+* パーミッションマーケティング — 客の**同意（許可）を得てから**売り込み、同意の範囲を**少しずつ広げる**
+ アフィリエイト — **成約したら報酬**を払って、他人のサイトで紹介してもらう
+ バイラルマーケティング — **口コミ・SNS**で人から人へ**勝手に広まる**仕組み（viral＝ウイルスのように）
)
( 価格の決め方
+* キャプティブ価格 — 本体を安く、消耗品で稼ぐ（プリンタとインク）
+ プライスライニング — 松竹梅の価格帯
+ 名声価格 — わざと高くして高級感
+* ターゲットリターン — 目標の**ROI**から価格を決める
+ ダイナミックプライシング — 需要に合わせて変える
- コストプラス — 原価＋マージン
)
( 売る場所（店とネット）
+ ボランタリーチェーン — 独立した店同士が仕入れなどを共同化
+ フランチャイズ — 本部（フランチャイザー）が看板・販売権・ノウハウを貸し、加盟店からロイヤリティを取る（コンビニ）
+ オムニチャネル — **1つの会社**の店・EC・アプリを**つなげる**（ネットで注文して店で受け取り）
+ O2O — ネットから実店舗へ誘導
)
( ネットのサービス・稼ぎ方
+ ロングテール — ニッチ商品の合計が無視できない
+ フリーミアム — 基本無料・高機能は有料
+* アグリゲーションサービス — **複数の会社**のサービスを**1か所にまとめて**見る・比べる（家計簿アプリ・価格比較サイト）
+ エスクローサービス — **第三者がお金を一時預かり**して安全に取引（フリマアプリの支払い）
)

## 決め方（ゲーム理論）
| 案 | 悪化 | 横ばい | 好転 | 最小 | 最大 | 合計 |
| 積極 | 50 | 150 | 500 | 50 | **500** | 700 |
| 継続 | 100 | 200 | 300 | 100 | 300 | 600 |
| 消極 | 400 | 250 | 200 | **200** | 400 | **850** |
( 確率がわからないとき（各行の最小・最大・合計を書き出す）
+* マクシミン — 最悪のなかで一番マシ（悲観）→ 消極
+* マクシマックス — 最高のなかで一番いい（楽観）→ 積極
+ ラプラス — 全部同じ確率とみなして期待値最大 → 消極
+ フルヴィッツ — 最大×α＋最小×(1−α)
+ ミニマックスリグレット — 「選ばなかった方が良かった」損（機会損失）の最大値が最小の案
)
(
-* 期待値原理 — 確率がわかるなら、利得×確率の合計が最大の案
+ デシジョンツリー — □＝自分が決める点、○＝確率で分かれる点
+* ナッシュ均衡 — 誰も**自分だけ戦略を変えても得しない**状態。相手の手を固定して自分の最適に印→印が重なるマス
+ ゼロ和ゲーム — 全員の利得の合計が0
)
! 期待金額価値は「収益 − 投資額」を先に出してから確率を掛ける。収益にそのまま掛けるとひっかけ

## 在庫と検査
@fig eoq | 経済的発注量（EOQ）
= #+ 在庫の公式
= 発注点 ＝ 調達期間の需要 ＋ 安全在庫
= EOQ ＝ √(2 × 年間需要 × 1回の発注費 ÷ 1個の年間保管費)
=   例）√(2×1200×100÷6) ＝ 200個
= 定期発注量 ＝ (調達期間＋発注間隔)の需要 − 在庫 − 注文残 ＋ 安全在庫
| | 定量発注 | 定期発注 |
| いつ | 在庫が**発注点**を切ったら | 決まった日ごと |
| いくつ | 決まった量（EOQ） | 毎回予測して決める |
| 向く品 | 安い・需要が安定（B） | 重要・需要が変動（A） |
(
-* ABC分析 — パレート図で重点管理。A＝定期発注、B＝定量発注、C＝2ビン法
+* OC曲線 — 不良率ごとの合格の確率（抜取検査）
+ 生産者危険 — 良いロットが不合格になる確率（作った側が損）
+ 消費者危険 — 悪いロットが合格しちゃう確率（買った側が損）
)

## お金
@fig breakeven | 損益分岐点（固定費500・変動費率0.2）
= #損益分岐点
= 損益分岐点売上高 ＝ 固定費 ÷ (1 − 変動費率)
= 変動費率 ＝ 変動費 ÷ 売上高
= 目標売上高 ＝ (固定費 ＋ 目標利益) ÷ (1 − 変動費率)
= 安全余裕率 ＝ (売上高 − 損益分岐点) ÷ 売上高
= 限界利益 ＝ 売上高 − 変動費
! 売上原価と販管費の**両方**に変動費・固定費が混ざってる。それぞれ足してから計算
+ 固定費が大きく変動費率が低い会社 — 売上が伸びると大きく儲かる、落ちると大赤字
@flow 売上高 >[−売上原価] 売上総利益 >[−販管費] 営業利益::本業 >[±営業外] 経常利益 >[±特別] 税引前当期純利益 >[−税] 当期純利益 || 利益の階段。「営業利益は？」で営業外まで引いたら×
(
- 貸借対照表（B/S） — ある**時点**の資産＝負債＋純資産
- 損益計算書（P/L） — ある**期間**の儲け
- キャッシュフロー計算書 — 営業・投資・財務のお金の出入り
- 減価償却（定額法） — (取得価額 − 残存価額) ÷ 耐用年数 を毎年費用に
- 棚卸資産 — 先入先出法など
)
= #+ 財務指標（会社の成績と体力）
= ROE ＝ 当期純利益 ÷ 自己資本
= ROA ＝ 当期純利益 ÷ 総資本
= 自己資本比率 ＝ 自己資本 ÷ 総資本（高いほど安全）
= 流動比率 ＝ 流動資産 ÷ 流動負債（高いほど安全）
= 固定比率 ＝ 固定資産 ÷ 自己資本（**低い**ほど安全）
= EVA ＝ 税引後営業利益 − 投下資本 × 資本コスト

## 投資するか決める指標（ROI・PBP・NPV・IRR）
| 指標 | 何を見る？ | 投資するのは |
| ROI | 投資に対して**何%**もうかるか | 目標の%を超えたら |
| PBP | **何年で**元が取れるか | 決めた期間より短ければ |
+| NPV | 将来のもうけを**今の価値**に直して、投資額より大きいか | **0より大きければ** |
+| IRR | NPVが**ちょうど0**になる利回り | **期待する利回りより大きければ** |
= #+ 投資の判断
= ROI ＝ 利益 ÷ 投資額
= 回収期間（PBP） ＝ 投資額 ÷ 毎年のもうけ
= NPV ＝ Σ 将来のお金 ÷ (1＋割引率)^年 − 投資額
= IRR ＝ NPVがちょうど0になる割引率
= 例）100万円投資して毎年30万円もうかる
=   ROI ＝ 30 ÷ 100 ＝ 30%、PBP ＝ 100 ÷ 30 ≒ 3.3年
( 名前と考え方
- ROI — 投資利益率（Return On Investment）
+* PBP — 回収期間（Pay Back Period）。お金の時間価値を考えないのが弱点
+* NPV — 正味現在価値（Net Present Value）
+ IRR — 内部収益率（Internal Rate of Return）
+* 現在価値 — 来年の100万円は今の100万円より安い（利息がつくから）。割引率10%なら来年の110万＝今の100万
)
! ROI は**割合**（%）、PBP は**年数**。「何年で元が取れるか」を ROI と取り違えない

- 守られる — 設計書・ソースコード・目的プログラム・マニュアル
+ やってOK — バックアップ用の複製、自社で使うための改変
+ やっちゃダメ — 子会社などに複製して配る、海賊版と**知ってて手に入れて**使う
+ クリエイティブ・コモンズ — 表示・非営利・改変禁止・継承などの条件を付けて利用を許可

+* 派遣で作った — **派遣先**のもの
+* 開発を委託（請負）した — 特に決めてなければ**受託した側**のもの
+ 著作者人格権 — 公表権・氏名表示権・同一性保持権。**譲渡できない**

## 守るルール
(
+* PL法（製造物責任法） — ソフトウェア**単体は対象外**。ソフトを組み込んだ機器は対象
+* 下請法 — 親事業者の都合で返品・減額・支払遅延・やり直し・受領拒否はダメ（下請側の責任ならOK）
+ 取適法 — 下請法が2026年1月から名前を変えた（委託事業者・中小受託事業者、手形払い禁止など）
- 不正アクセス禁止法 — なりすましログイン・他人のID/パスワードを無断で教えるのもNG
- 刑法 — 不正指令電磁的記録（ウイルス作成・提供）、電子計算機損壊等業務妨害
+* 特定電子メール法 — 広告メールは**オプトイン**（同意した人にだけ送る）が原則
+ 電子署名法 — 電子署名に押印と同じ効力
+ サイバーセキュリティ基本法 — 国の責務。司令塔は NISC（内閣サイバーセキュリティセンター）→ 2025年7月から**国家サイバー統括室**
)
( 個人情報保護法
- 個人情報 — 生きてる個人を特定できる情報（顔画像・音声も）
+ 要配慮個人情報 — 病歴・犯罪歴など。取得に本人の同意が必要
+* 匿名加工情報 — 特定できず**元に戻せない**。同意なしで第三者に出せる
+ 仮名加工情報 — 照合すれば特定できる。原則社内での分析用
+ 個人識別符号 — それ単体で個人を特定できる番号・データ（顔・指紋のデータ、マイナンバー、旅券番号）
+ 第三者提供 — 原則**本人の同意**が要る。業務委託・合併・共同利用は第三者提供にあたらない
+ 外国の第三者への提供（越境移転） — 原則**本人の同意**。相手の国の制度などの情報も本人に伝える
+ 漏えい等の報告 — 要配慮・財産的被害・**1,000人超**などは個人情報保護委員会へ報告し、本人にも通知
)
