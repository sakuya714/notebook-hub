## E-R図
(
-* 1対多 — **多の側**が1の側の主キーを**外部キー**として持つ
+* 多対多 — 間に**連関エンティティ**を入れて1対多×2に。その主キー＝両側の主キーの組
+ E-R図の穴埋め — 主キーを持つ側が「1」、外部キーを持つ側が「多」
+ 「1回の請求を複数回で入金」「複数の請求を1回で入金」 — 両方あれば多対多
)

## キーの種類（入れ子で考える）
@lad キーの入れ子（例：社員表＝社員番号・免許証番号・氏名…） | 広い | 狭い
+スーパーキー :: 1行を特定**できれば**何でも。余計な列が入っててもいい。例 {社員番号, 氏名}
候補キー :: スーパーキーから余計な列を削りきった**極小**の組。例 {社員番号}・{免許証番号}
主キー :: 候補キーから**1つ選んだ代表**。重複不可＋NULL不可。例 社員番号
@end
(
+ 代替キー — 主キーに**選ばれなかった**候補キー（例：免許証番号）
- 外部キー — **他の表**の主キーを**参照**する列。表どうしを**つなぐ**
+ 代理キー（サロゲートキー） — 意味のない連番などを人工的に付けた主キー
)

## 正規化
@stack 正規化の階段（下に行くほど分ける）
非正規形 :: 1人に資格が何行もぶら下がる（繰返し）
第1正規形 :: 繰返しをなくす（1マス1値）
第2正規形 :: **主キーの一部**だけで決まる列を分ける（部分関数従属）
第3正規形 :: **主キー以外**で決まる列を分ける（推移的関数従属）
+ボイス・コッド正規形 :: 決定する側が必ず候補キー
@end
(
- 関数従属 X→Y — Xが決まるとYが1つに決まる
+* 第2正規化が起きるのは — 主キーが**複数列**の表だけ
+ どこまで正規化されてる？ — 主キー1列なら第2以上確定→キー以外どうしの従属があれば第3じゃない
+ 正規化の目的 — 更新時異状（データ矛盾）を防ぐ。欠点は結合が増えて遅い→あえて崩す＝非正規化
)

## 制約と表定義
| 制約 | 書き方 | 意味 |
| 主キー | PRIMARY KEY | 一意＋NOT NULL |
+| 一意性 | UNIQUE | 重複NG。**NULLはOK** |
| 非ナル | NOT NULL | 空値NG |
| 参照 | REFERENCES / FOREIGN KEY | 外部キー |
+| 検査 | CHECK(単価 > 0) | 条件を満たすか |
( 参照動作（親＝注文を消したら、子＝注文明細はどうなる？）
+* CASCADE — 子も**一緒に**消える・変わる（**滝**のように連鎖）
+ RESTRICT — 子がいたら親の削除を**すぐ拒否**
+ NO ACTION — 子がいたら拒否。確認は**処理の最後**（**既定**）
+ SET NULL — 子の外部キーを**NULL**に（親なしにする）
+ SET DEFAULT — 子の外部キーを**既定値**に（決まった親に付け替え）
)
! 参照制約で拒否されうるのは「外部キー側への追加」と「参照される側の削除」

## SELECTを読む
@flow FROM::表・直積 > WHERE::行を絞る > GROUP BY::まとめる > HAVING::グループを絞る > SELECT::列を選ぶ > ORDER BY::並べる || この順に仮の表を書いていけば必ず読める
( 関係演算
-* 選択 — **行**を取り出す＝WHERE
-* 射影 — **列**を取り出す＝SELECT
- 結合 — 共通列で2表をつなぐ＝直積＋選択
- 和・差・積 — UNION／EXCEPT／INTERSECT（同じ列構成どうし）
)
( 書くときの注意
+* 集合関数はWHEREで使えない — SUM・AVG・COUNTはHAVINGかSELECTで
+ COUNT(*) — NULL行も数える。COUNT(列)＝NULLを除く
+* 同姓同名を探す — GROUP BY 氏名 HAVING COUNT(*) > 1
- LIKE — `%`＝0文字以上、`_`＝1文字
+ NULLの判定 — `IS NULL`（`= NULL`は書けない）
)

## 結合と副問合せ
(
- 内結合 — 両方にある行だけ
+* 左外結合 — 左の表は全部残す。相手がなければNULL→**行数≧左の表の行数**
+ 副問合せ — （SELECT…）の結果を使う。比較演算子と使うなら1行1列が必要
+* 相関副問合せ — 副問合せの中に**外側の表**が出てくる。外側の1行ずつ実行
+* EXISTS — 1行でもあれば真。NOT EXISTS＝1行もなければ真
)
! NOT EXISTSの境界：「在庫数＞30」に30は入らない。外側の表を1行ずつトレースする

## 更新とビュー
(
- UPDATE・DELETE — **WHEREを書き忘れると全行**
+ UNIQUE違反の判定 — NULLを含む組は重複扱いにならない。既にある組を作ったらNG
+* ビュー — 名前を付けた導出表（仮想の表）。実データは持たない
+* 更新できないビュー — 集合関数・DISTINCT・GROUP BY・HAVING・計算式がある（元の行に戻せない）
- GRANT／REVOKE — 権限を与える／取り消す
)

## トランザクション
( ACID
-* A 原子性 — 全部やるか、全くやらないか
- C 一貫性 — 前後で矛盾しない
-* I 隔離性（独立性） — 同時に動かしても順番にやったのと同じ結果（直列可能性）
-* D 耐久性 — コミットしたら障害が起きても消えない
)
( 同時実行の問題
- ロストアップデート — 後の更新で先の更新が消える
+ ダーティリード — **未コミット**のデータを読む
+ ノンリピータブルリード — 2回読んだら間に**更新**されて値が違う
+ ファントムリード — 2回検索したら間に**追加**されて行が増えてる
)
| 相手→ | 共有ロック | 専有ロック |
| 共有ロック中 | ○ | × |
| 専有ロック中 | × | × |
(
+* 2相ロック — 使うものを全部ロック→終わったら全部解除。解除後は再ロックしない→直列可能性を保証
+ ロックの粒度 — 小さい（行）ほど並行性↑・管理の手間↑
+ 分離レベル — READ UNCOMMITTED＜READ COMMITTED＜REPEATABLE READ＜**SERIALIZABLE**（一番厳しい）
+ 楽観的排他制御 — ロックせずに処理し、更新時に**変更されていないか確認**（版番号）
+ WAL（ログ先行書込み） — DBを更新する**前に必ずログ**を書く
)

## LANの送り方（誰がいつ送るか）
| 方式 | 会議で例えると | キーワード |
| CSMA/CD | 静かなら話す。**かぶったら少し待って言い直す**（有線） | 「**衝突**を検出」「**ランダム**な時間待って再送」 |
+| CSMA/CA | 静かでも**少し待ってから**話す（無線） | 「衝突を**回避**」「ACK」 |
| トークンパッシング | **輪になってマイクを回す** | 「**環状**」「**巡回**」「送信権」 |
+| TDMA | **時間割**で話す順番が決まってる（時分割） | 「**タイムスロット**」 |
+| 優先度制御 | **偉い順**にマイクを渡す | 「**順位付け**」 |
! 「衝突」「ランダムに待って再送」なら **CSMA/CD**。トークン・TDMA・優先度制御は最初から順番が決まっていて、そもそもぶつからない
(
- CSMA/CDの遅延 — 回線の使用率30%くらいから急に増える
+ 隠れ端末問題 — 端末同士が見えずにAPで衝突 → RTS/CTSで予約
)

## IPの周りのプロトコルとポート番号
( IPを支える（住所・自動設定・エラー）
-* ARP — **IP→MAC**を調べる。要求はブロードキャスト、応答はユニキャスト
- RARP — ARPの逆。**MAC→IP**を調べる
-* DHCP — IPアドレスを自動で配る。UDP。最初は送信元0.0.0.0→宛先255.255.255.255
+ DHCPリレーエージェント — ルータはブロードキャストを通さないので、別ネットワークのDHCPサーバへ中継
- ICMP — エラー通知。pingで疎通確認
)
( 冗長化・接続・監視・名前

## 鍵の使い分け（最重要）
@fig keys | 誰の・どっちの鍵？

(
+* 署名の検証 — 送信者の**公開鍵**で署名から戻したハッシュ値と、届いた本文のハッシュ値が**一致**すれば改ざんなし・本人

)
( 通信や弱点を突く
+ MITB — ブラウザに入り込んで通信を改ざん（ネットバンキング）
+ リプレイ攻撃 — 盗んだ認証情報をそのまま再送 → ワンタイムパスワード・チャレンジレスポンスで対策
+ ARPスプーフィング — 偽のARP応答で通信を自分に流させる
+* DNSキャッシュポイズニング — キャッシュDNSに偽の答えを覚えさせて偽サイトへ → **問合せID・ポートのランダム化**、DNSSEC、外からの再帰問合せ拒否
+* ゼロデイ攻撃 — パッチが出る**前**の脆弱性を突く
+* エクスプロイトコード — **脆弱性を突く**プログラム（Exploit＝悪用）。守る側の検証にも使う
+* サイドチャネル攻撃 — 正面から解かず、**電力・時間・電磁波・故障**など横から漏れる情報で鍵を盗む
+ サイドチャネルの種類 — タイミング攻撃（時間）・電力解析・電磁波解析（**テンペスト**）・故障利用
)
( 守る・調べる
+* 耐タンパ性 — 中身を解析・改ざんされにくい度合い（TPM はこれを持つチップ）
+ サンドボックス — 隔離した場所で動かして様子を見る
+ ハニーポット — わざと侵入しやすくした**おとり**で攻撃を観察
+ 検疫ネットワーク — つなぐ前に端末を検査し、問題があれば隔離
+ ファジング — 変なデータを大量に入れて脆弱性を探す
+ デジタルフォレンジックス — 証拠を法的に使える形で集めて保全
+ ダークネット — 使われてないIP空間。届く通信は怪しい
)

## 起動を守る（セキュアブート・TPM）
@flow ファームウェア::BIOS／UEFI > ブートローダ::OSを呼ぶ案内係 > OS::Windows・macOS > ドライバ・アプリ || PCが起動する流れ。セキュアブートはブートローダとOSを読む所で署名を確かめる
! BIOSパスワード・HDDパスワードは**人**をパスワードで確かめる。セキュアブートは**プログラム**を署名で確かめる
(
+* セキュアブート — 起動時に**デジタル署名を検証**し、正しいものだけ実行。偽物なら起動しない（UEFIの機能）
+ ブートキット — OSより**先に**動くマルウェア。OS起動後のウイルス対策では**手遅れ**
- BIOS — 昔の起動用ファームウェア（Basic Input/Output System）
+ UEFI — BIOSの**後継**（Unified Extensible Firmware Interface）
+ ブートローダ — OSを呼び出す**案内係**
+* TPM — PCに載っている**鍵の金庫チップ**。起動時の状態を記録・検証（Trusted Platform Module）
)

## 攻撃の段取りと社会の仕組み
@flow 偵察 > 武器化 > 配送 > 攻撃 > インストール > 遠隔操作 > 目的実行 || サイバーキルチェーン（7段階）。SNSで社員を調べる＝偵察
( 対応する組織・しくみ
+* 早期警戒パートナーシップ — 脆弱性情報は**IPAが受付・JPCERT/CCが調整・JVNで公表**
+ CSIRT — インシデント対応チーム（6種類は下）。J-CRAT＝標的型攻撃のレスキュー隊
+* トリアージ — 対応の優先順位付け（インシデントハンドリングの1つ）
+ SOC — 24時間監視して攻撃を**検知・分析**する組織（対応するのはCSIRT）
+ セキュリティバイデザイン — 企画・設計の段階からセキュリティを組み込む
)
( 攻撃と不正を知る
+* MITRE ATT&CK — 実際の攻撃を戦術・技術で分類した知識ベース
+* 不正のトライアングル — 機会・動機・正当化がそろうと不正が起きる
+ シャドーIT — 会社が許可してないIT機器・サービスを勝手に使う
)
( お墨付きの制度（国・第三者が評価する）
+* ISMAP — 政府が使える**クラウドサービス**を事前に評価して**登録**する制度（イスマップ）
+ ISMS適合性評価制度 — 会社の**情報セキュリティ管理**の仕組み（JIS Q 27001）を第三者が認証
+ ISMSクラウドセキュリティ認証 — ISMSに加えて**クラウド向けの管理策**（ISO/IEC 27017）を認証
+ プライバシーマーク — **個人情報**を適切に扱う**会社**を認定（JIS Q 15001）
+ CRYPTREC — 電子政府推奨暗号リスト（推奨・推奨候補・運用監視）
)
( CSIRT の6種類（違いは「誰のために動くか」だけ）
+ 組織内CSIRT — **自分の会社**の事件に対応（ふつう「CSIRT」と言えばこれ）
+ 国際連携CSIRT — **国の代表**として海外と連絡（JPCERT/CC）
+* コーディネーションセンター — **他のCSIRT同士**の情報連携・調整役
+ 分析センター — 攻撃の**傾向分析**・マルウェア解析・注意喚起
+ ベンダーチーム（PSIRT） — **自社製品**の脆弱性を直してパッチを出す
+ インシデントレスポンスプロバイダ — CSIRTの仕事を**有償で代行**（セキュリティ会社）
)

## 脆弱性の名札（CVE・CWE・CVSS…）
( 頭のCは全部 Common。2文字目の英単語で見分ける
+* CVE — **個別の脆弱性**の番号（**V**ulnerability）。例：CVE-2021-44228。共通脆弱性識別子
+* CWE — 脆弱性の**種類**の番号（**W**eakness）。例：SQLインジェクション＝CWE-89
+ CCE — セキュリティ**設定**の項目（**C**onfiguration）
+ CPE — **製品**の名前の付け方（**P**latform）
+* CVSS — 深刻度を**点数化**（0.0〜10.0）（**S**coring）。基本・脅威・環境で評価
+ SCAP — CVE・CCE・CPE・CVSS＋検査用の言語で、チェックを自動化する仕組み（CWEは入らない）
)
@flow CPE::どの製品？ Apache Log4j > CVE::どの脆弱性？ CVE-2021-44228 > CWE::どんな種類の弱点？ > +CVSS::どれだけ危ない？ 10.0（最高） || Log4j の脆弱性で4つをつなげると。JVN で CVE を引くと CVSS や CWE も一緒に載っている
! CVE＝**事件ごと**の番号（この製品のこのバグ）、CWE＝**手口の種類**の番号。ここを入れ替えた選択肢が一番多い
