## 〇PUの仲間（★） {{learning/応用情報技術者:02-1#〇PUの仲間}}
==何の計算が得意かで名前が変わる==。CPU は何でも順番に、GPU は単純な計算を大量に同時に。

| CPU | **何でも**。複雑な処理を順番に（分岐予測もここ） | 料理長 |
+| GPU | **単純な計算を大量に同時に**（画像・**行列演算**・AI の学習） | 大量の見習い |
| FPU | **小数（浮動小数点）**の計算 | 計量の専門家 |
| NPU | **AI の推論**を省電力で | AI 専門のシェフ |
| TPU | Google の **AI 専用** | — |
| DSP | **音声・映像の信号処理** | 音響担当 |
( つながり
- LSI — **チップそのもの**（入れ物）。CPU も GPU も LSI の中の回路
- SoC — CPU・GPU・NPU・メモリなどを**1つのチップ**にまとめたもの（スマホ・Apple M シリーズ）
- MCU（マイコン） — CPU・メモリ・入出力を1チップにした小さなコンピュータ（家電・組込み）
- CPI — 部品ではなく**速さの指標**。1命令に何クロックかかるか（小さいほど速い）

## マルチコアとパイプライン（★） {{learning/応用情報技術者:02-1#CPUを速くする}}

| 名前 | 一言で | 厨房で例えると |
+| ヘテロジニアス | **違う種類**のコアを混ぜる（高性能＋省電力、CPU＋GPU） | 寿司職人＋パティシエ |

| 止めない工夫 | 一言で |

- サイクル — CPU の時計の**1カチッ**（時間の単位）

## 割込みとコンテキスト {{learning/応用情報技術者:02-1#割込み}}
==割込みは緊急事態での強制中断、タスク切替えは OS が順番に入れ替えること==。別物。
| | 割込み | タスク切替え |
| 一言で | 何をしていても**強制的に中断** | OS が**順番に仕事を入れ替える** |

## メモリの家系図（★） {{learning/応用情報技術者:02-1#メモリ}}

+ ユニファイドメモリ — CPU と GPU が**1つの主記憶を共有**。主記憶の一部を画面の表示用に使う（コピーが要らず速い。Apple M シリーズ）

## キャッシュの置き方 {{learning/応用情報技術者:02-1#キャッシュ}}
==どこに置いてもいいのがフル、1か所に決まるのがダイレクト、エリアだけ決まるのがセット==。
| 方式 | ルール | 駐車場で例えると |
| ダイレクトマップ | 入れる場所が**1か所に決まる**（1対1） | **指定席** |
+| フルアソシエイティブ | **どこに入れてもいい** | **自由席**（探すとき全部見て回る） |
| セットアソシエイティブ | **エリアは決まる**、エリアの中は自由 | エリア指定＋中は自由（今の CPU はほぼこれ） |
- ブロック — データを入れる**1マス分の箱**。主記憶のブロック＝車、キャッシュのブロック＝駐車スペース
- セット — 駐車スペースを数台分ずつまとめた**エリア**
> 「一意に定まる・固定」→ ダイレクト、「**どのブロックにも**」→ フル、「セット」→ セット

## 仮想記憶と断片化（★） {{learning/応用情報技術者:02-3#仮想記憶}}
主記憶＝**勉強机**（狭いが速い）、ディスク＝**本棚**（広いが遠い）。机が狭くても本棚を机の一部のように使うのが仮想記憶。
| 置き方 | 区切り方 | 弱点 |
| ページング | **同じ大きさ**（固定長） | 最後のページが余る（**内部断片化**） |
+| セグメンテーション | **意味のまとまり**（可変長） | 隙間ができる（**外部断片化**） |
+ 外部断片化 — **空きの合計は足りるのに、ばらばらで入らない**（10マス中、空き4と3で計7あっても、続いた5マスがない）
- コンパクション — 使っている所を端に寄せて**空きを1か所にまとめる**
( 机にない！（ページフォールト）
- ページイン ／ ページアウト — 本棚から持ってくる ／ 机が満杯なので片付ける
- FIFO — **一番最初に置いた**ものを片付ける
+ LRU — **一番長く使っていない**ものを片付ける
- LFU — **使った回数が一番少ない**ものを片付ける
)
- ページテーブル — どのページが机・本棚のどこにあるかの**台帳**（多段にすれば必要な分だけ作ればいい）
- ガーベジコレクション — 使い終わったメモリを**自動で回収**（机のゴミを捨てる係）。ページフォールトとは無関係
@pair 断片化 | 外部断片化 | 内部断片化 | 可変長で隙間が散らばる（セグメンテーション）／ 固定長で最後が余る（ページング） | H3

## 誤り検出と訂正（★） {{learning/応用情報技術者:01-1#符号}}
==訂正までできるのは垂直水平パリティとハミング符号だけ（どちらも1ビット）==。
| 方式 | 必ず検出 | 訂正 | 一言で |
| パリティ（1方向） | 1ビット | × | 1の数を偶数にそろえる |
+| 垂直水平パリティ | 3ビット | **1ビット** | 行と列の**交差点**で場所を特定 |
+| ハミング符号 | **2ビット** | **1ビット** | 検査ビットで**壊れた位置の番号**を出す |
| CRC | **バースト誤り**に強い | × | **生成多項式**で割った余りを付ける |
| チェックサム | 保証なし | × | 合計を付ける（打ち消し合うと見逃す） |
( なぜ2ビット以上は訂正できない？
- 2ビット — 「1・2行目と1・2列目が変」は (1,1)(2,2) でも (1,2)(2,1) でも同じに見える → 場所が決まらない
- 4ビット — **長方形の角**にそろうと全部の行と列が偶数に戻ってすり抜ける → 必ず検出は3ビットまで
+ ハミング符号 — 検査ビットが「誤りは1・3・5・7番目のどれか？」のような**はい・いいえ**を担当し、答えを並べた2進数（101＝5）が壊れた位置。2ビット壊れると関係ない番号を指す
)
@fig parity | 垂直水平パリティ | 受け取る側に見えるのは「どの行・どの列が変か」だけ
- 対処 — **ARQ**（見つけたら再送してもらう）／**FEC**（受け取った側が自分で直す：ハミング符号）
> ハミング＝「**1訂正・2検出**」。CRC＝「**連続した誤り**」「**生成多項式**」、検出だけ
@pair 誤り | ハミング符号 | CRC | 1ビット訂正・2ビット検出 ／ バースト誤りに強いが検出だけ | H3

@ch H4 | OSとプログラム | OS の中身 → OSS → 再入可能 → 排他制御 → 周期タスク → 開発の道具 → 文字コード

flow: カーネル::OSの心臓 > OSS::公開とライセンス > +再入可能::同時に使える > セマフォ::取り合いの整理券 > 周期タスク::締め切りに間に合うか
レシピ本（プログラム）と料理人（タスク）の例えで、再入・セマフォ・周期タスクがつながる。

## OSSとライセンス（★） {{learning/応用情報技術者:02-3#OSS}}
==ソースが公開されていて、ライセンスを守れば誰でも使える・直せる・配れる==。
| よくある誤解 | 正しくは |
| 無料でないといけない | **有料で売ってもいい** |
+| 作者は著作権を放棄した | **著作権は作者にある**（放棄したものはパブリックドメインで別物） |
| 作者が保証してくれる | **無保証**が原則 |
+| 商用禁止などを付けてもいい | **利用者や用途を制限してはいけない** |

## 再使用・再入・再帰（★） {{learning/応用情報技術者:01-2#プログラムとメモリ}}
プログラム＝**レシピ本**、タスク＝**料理人**、変数＝途中経過の**メモ**。==再使用 ⊃ 再入 ⊃ 再帰==（内側ほど厳しい）。
@lad 3つの「再〜」 | 広い（ゆるい） | 狭い（厳しい）
再使用可能 :: 何度も使える。ただし**1人ずつ順番**（メモを本に直接書くので、使ったら消して交代）

再帰可能 :: レシピの途中で**自分をもう一度最初から**使える（同じ本を2重に使うので、再入できないと無理）

- 再配置可能 — メモリの**どこに置いても**動く。入れ子とは**別枠**
- オーバーレイ — 必要な部分だけ補助記憶から読み込みながら動く
! 「再使用可能なら再入可能」は×（外から内は言い切れない）。「再帰的なら再入可能」は○。「〇〇だが△△ではない」と無関係な性質を言い切る選択肢はほぼひっかけ
@pair 再〜 | 再使用可能 | 再入可能 | ロードし直さず繰り返し（1人ずつ）／ 同時に複数から呼ばれても正しい | H4

## セマフォとマルチスレッド {{learning/応用情報技術者:02-3#排他制御}}
==セマフォは共有の資源を取り合わないための整理券（カウンタ）==。
+ セマフォ — 使うとき **P操作**で −1、終わったら **V操作**で ＋1、**0なら空くまで待つ**（排他制御）
> トイレの空き札：個室2つ＝セマフォ2。入るとき −1、出るとき ＋1、0なら満室
- マルチスレッド — 1つのプロセス（アプリ）の中で、作業を**複数のスレッド**に分けて並行に進める。同じメモリ（冷蔵庫）を共有するので、取り合いを**セマフォで交通整理**する
- ラウンドロビン — 一定時間（タイムクウォンタム）ずつ**順番に** CPU を渡す
- キュー — 先入れ先出しのデータ構造。排他制御の機能はない

## 周期タスク（★） {{learning/応用情報技術者:02-3}}
==周期＝次の仕事が届くまでの締め切り==。優先度の高い A が割り込むので、B は A の隙間でしか進めない。
@fig sched | Bの1回目が周期までに終わるか | 時刻0は A と B が同時に来る一番きつい瞬間。ここで間に合えば以降も間に合う
@steps 解き方
A を周期ごとに先に塗る :: 優先度が高いので、届いたらすぐ割り込む
空いたマスに B を左から詰める :: B は A の隙間でしか進めない
B が終わった時刻 ≦ B の周期 なら OK :: 周期＝次の B が届くまでの締め切り
@end
+ 最大実行時間 — 1回分の仕事を終えるのに必要な CPU 時間の**合計の上限**（最悪のケース）。「1回で4ミリ秒ずつ進む」という意味ではない
- プリエンプティブ — 優先度の高い仕事が来たら、今の仕事を**中断して横取り**できる
> 通学と同じ：最大30分かかるなら30分で計算する。いつもの20分で計算すると混んだ日に遅刻する
! 「A 3 ＋ B 4 ＝ 7 ≦ 9 だから OK」は×。A は**周期ごとに何回も割り込む**ので、B の周期の中で A が何回来るか数える

## 文字コードとXML（★）
UTF-8 も UTF-16 も **Unicode**（世界中の文字に番号を振った表）を、何バイトで記録するかの違い。
| | UTF-8 | UTF-16 |
| 基本の単位 | **1バイト** | **2バイト** |
| 英数字 ／ 日本語 | 1バイト ／ 3バイト | 2バイト ／ 2バイト |
+| XML での目印 | 何もなければ **UTF-8**（既定） | 先頭の **BOM**（見えない2バイト）で判別 |
| 使われ方 | Web・ファイルの標準 | Windows・Java の内部 |
+ XML宣言 — 1行目の `<?xml version="1.0" encoding="Shift_JIS"?>`。**UTF-8・UTF-16 なら encoding を省略できる**。それ以外（Shift_JIS・EUC-JP）は書かないと UTF-8 と思われて文字化けする
- 誰が決める？ — 文字コードは**保存する側**（エディタ。ふだんは自動で UTF-8）が決め、**読む側**は先頭の BOM の有無で**見分ける**だけ。BOM はエディタが保存時に自動で付ける
- BOM がなぜ要る？ — UTF-16 は2バイトの**並び順**（ビッグエンディアン FE FF ／ リトル FF FE）が機械で違うので、先頭に目印を置く

## ヒープソートと線形探索 {{learning/応用情報技術者:01-2#整列}}
+ ヒープソート — 根（最大値）と**最後の葉を入れ替え**、最後を「確定」として木から外す → 残りをヒープに直す、を繰り返す。別の箱は使わず、**配列の後ろに確定ゾーンがたまる**（最大ヒープ → 昇順、O(n log n)、追加メモリ不要）
> 大きい順に**後ろの席から**座らせていく。座った人はもう木のメンバーではない
- 線形探索の平均回数 — 見つかるなら (n + 1) ÷ 2 回、見つからなければ n 回。計算は {{K2#線形探索の平均}}
